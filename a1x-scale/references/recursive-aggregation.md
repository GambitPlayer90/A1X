# Evidence-aware recursive self-aggregation

## Preconditions

Use aggregation after independent candidates exist, or use single-parent closure when one executed partial witness has a concrete open edge. Maintain population size `N` larger than aggregation subset size `K`. Small `K` preserves more diversity; large `K` increases synthesis pressure and mode-collapse risk. Choose a bounded number of rounds `T` and measure progress after each. A1X uses two distinct operators: protected `K=1` witness closure deepens one source-faithful lineage, while `K=2` recombination tests compatibility between independently grounded components.

## Single-parent witness closure

Activate a protected closure lane when the parent has concrete execution, a reached phase or measured phase-local signal, an open stable prerequisite, and no terminal witness. Give it the complete immutable parent evidence packet. It must preserve target, root cause, consumer, actor model, and reached prefix; work only on the first open closure edge; and return either a later phase, a narrower/resolved prerequisite with artifact evidence, or a mechanism-specific refutation. For precision mechanisms, it may generate or mutate the parent harness, build an exact integer mirror, map revert holes, snapshot the reached prefix, and optimize invariant/share-rate/internal-credit drift before final profit.

## Round

For each child:

1. sample a subset stratified across mechanisms, consumers, and evidence where possible;
2. present structured candidate records, including contradictions and failed attempts;
3. ask the aggregator to produce one coherent hypothesis/path, explicitly checking component compatibility;
4. execute the child against the same security oracle;
5. promote it only if it advances a witness phase, closes/narrows an inherited prerequisite, improves source fidelity/setup purity, adds stronger evidence, or establishes a compatible new causal edge without regressing the parent lineage;
6. preserve distinct parents, near-misses, and refuting records in the active pool or reserve;
7. inject a fresh blind lane so recursive synthesis cannot eliminate all independent search.

## Compatibility checks

Before combining call order, amounts, or helper logic, verify that candidates share compatible starting state, target implementation/configuration, actor permissions, assets/units, transaction boundaries, and external dependencies. A parameter optimized for one state may invalidate another candidate's prerequisite.

## Diversity controls

Track runtime-owned lineage, anchored root-cause family, consumer, reached-state fingerprint, artifact-bound causal identity, action-sequence distance, witness phase, inherited prerequisite states, and evidence level. Use family-first active allocation, a persistent reserve, stratified subsets, fresh independent candidates, and limited aggregation depth. Lane/round IDs and free-text family overlap never establish progress or compatibility. Do not infer quality from majority agreement; several candidates may share the same false assumption.

## Verification

External execution and protocol-specific properties outrank self-verification. Repeated sampling separates coverage from precision: population width increases the chance of containing a useful mechanism, while the execution/property verifier determines whether it survives. Track no-gain counters per lineage; an unrelated fresh lane must not conceal a stalled high-value thread. Treat newly added open prerequisites or attack-path setup taint as regression unless the child simultaneously advances a stronger grounded phase or closes an inherited edge. Stop after every active lineage exhausts its configured marginal-gain budget rather than assuming more recursion is always better.
